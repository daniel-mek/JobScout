# Phase 4: discovery and saving

`/discover` shows owner-scoped, database-paginated jobs, ordered by recorded Application Priority with explicit interest as a small tie-breaker. Views include For You, Fresh Opportunities, Excellent Matches, Reasonable Reaches and Recently Discovered. Cards show salary/period/currency when known, posted/discovered ages, source attribution/links/count, availability, recorded scores, seniority and recommendation. Missing scores remain pending; changed profile versions are flagged. Matching stays in the Phase 3 worker or explicit one-job calculation.

Filters cover role family, title, company, location, arrangement, employment type, salary/currency, minimum scores, recommendation, early-career category, posting freshness, source, saved and reviewed state. Search strings escape SQL wildcards. Role-family filtering is a conservative title-keyword interpretation of the persisted taxonomy, not a new semantic classifier. Query state survives URL navigation. `/discovery-searches` persists named, validated filter snapshots; reopening a search applies them to the current catalog. These are separate from existing source-ingestion searches; automatic per-search schedules remain Phase 7.

`/saved-jobs` retains saved time and listing revision plus editable notes/deadline. Unsaving preserves the canonical job and notes. Saved jobs remain visible when archived or dismissed. Save/dismiss records explicit review state; reviewed/unreviewed can also be set deliberately. Interested/Not Interested and negative reasons are reversible. Explicit dismissal hides a job from default discovery; positive interest only breaks ranking ties. Feedback never silently becomes a hard requirement.

`/brief` generates an on-demand UTC daily brief from up to 100 highest-priority active jobs, with separate excellent, strong-apply, fresh-reach and needs-review sections. It uses jobs discovered that day, excludes dismissed jobs, and leaves sections empty instead of adding filler. Followed-company sections await Phase 7. Original attribution and links are retained; no descriptions are copied into a separate archive.

`/notifications` provides owner-scoped read/unread controls, pagination and notification preferences. Matching emits deduplicated high-match/fresh-opportunity events for qualifying job revisions; source searches emit completion events. Later-phase notification types are reserved in preferences, but no application/calendar/email events are invented and no external messages are sent. Queue/provider operation and source approval remain unchanged.

Migrations `7bbad47051b0` and `6c74ed3c6e46` add review, notification/preference and saved-filter tables. Apply through the existing Alembic release procedure. Every mutation uses account ownership and CSRF checks. Saved-job versions are references to permitted canonical history, never a workaround for source retention rules. New records do not alter the legacy tracker.
